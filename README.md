# Дверной тренд — новая версия сайта (Next.js + админка)

Современный сайт магазина дверей: каталог с карточками товаров, страницы моделей, отзывы
с модерацией, заявки, блог и полноценная панель управления. В отличие от статической версии
в папке `GOTOVO`, здесь есть сервер: правки из админки сразу видны всем посетителям.

## Стек

- **Next.js 15** (App Router, Server Components) + **React 19** + **TypeScript**
- **Tailwind CSS 4** — своя дизайн-система (лесной зелёный, латунь, кремовый фон, антиква в заголовках)
- **Хранилище** — JSON-файл `data/db.json` с атомарной записью (см. «Про базу данных»)
- **sharp** — приём и сжатие фото прямо в админке
- **Шрифты** — Manrope + Cormorant Garamond, лежат локально в `public/fonts` (без запросов к Google)

## Быстрый старт

```bash
# 1. зависимости
pnpm install

# 2. переменные окружения
cp .env.example .env.local      # Windows: copy .env.example .env.local
#   ADMIN_PASSWORD  — пароль в админку
#   AUTH_SECRET     — любая длинная строка для подписи cookie

# 3. демо-данные (категории, 59 дверей, 3 отзыва) + перенос фото
node scripts/seed.mjs

# 4. разработка / прод
pnpm dev        # http://localhost:3000
pnpm build && pnpm start

# 5. проверка, что админка действительно закрыта
pnpm smoke      # http://127.0.0.1:3000 по умолчанию
```

Требуется **Node.js 22.5+** (проверено на 24).

## Админка

`/admin` → пароль из `ADMIN_PASSWORD` (по умолчанию `admin123`, поменяйте).

- **Товары** — список сгруппирован по разделам и подразделам, поиск, создание, редактирование,
  удаление, скрытие с сайта, загрузка фото (сжимается до 1200×1600 и конвертируется в JPEG).
- **Заявки** — все обращения с сайта, статусы «новая / в работе / готово», телефон клиента,
  комментарий, привязка к модели.
- **Отзывы** — модерация: опубликовать, отклонить, удалить.
- **Настройки** — телефон, часы работы, адрес, e-mail, ссылки на Telegram/MAX/VK, география доставки,
  текст на главной. Всё это сразу подставляется в шапку, подвал и контакты.

Авторизация: пароль → HMAC-подписанный httpOnly cookie на 7 дней (`src/lib/auth.ts`),
проверка в `middleware.ts` на всех `/admin/*`. Пароль сравнивается в постоянном времени.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/leads` | заявка с сайта (имя, телефон, комментарий, тип, товар) |
| `POST` | `/api/reviews` | отзыв (создаётся со статусом `pending`) |
| `POST` | `/api/admin/login` | вход, `DELETE` — выход |
| `GET/POST` | `/api/admin/products` | список / создание товара |
| `PATCH/DELETE` | `/api/admin/products/[id]` | правка / удаление |
| `POST` | `/api/admin/upload` | загрузка фото (multipart) |
| `PATCH/DELETE` | `/api/admin/leads/[id]` | статус / удаление заявки |
| `PATCH/DELETE` | `/api/admin/reviews/[id]` | модерация отзыва |
| `GET/POST` | `/api/admin/settings` | чтение / сохранение настроек |

Все `/api/admin/*` проверяют сессию и отвечают `401` без неё.

## Telegram-уведомления

Заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env.local` — новые заявки будут
приходить в чат (`src/app/api/leads/route.ts`). Если переменные пустые, заявки просто
сохраняются в базе и видны в админке.

## Про базу данных

Сейчас данные лежат в JSON-файле `data/db.json` (атомарная запись: временный файл + `rename`).
Этого достаточно для одного магазина с одним-двумя администраторами: каталог читается из памяти
и прекрасно держит тысячи товаров.

Почему не SQLite: `node:sqlite` в Next.js приходится протаскивать через конфиг webpack,
а `better-sqlite3` требует нативной сборки. JSON-хранилище убирает эти риски при деплое.
Когда понадобится несколько администраторов одновременно или история изменений — переезд
на Postgres занимает один вечер: весь доступ к данным собран в `src/lib/store.ts` и
`src/lib/catalog.ts`, интерфейс функций менять не придётся.

## Деплой

Нужен хостинг с Node.js (VPS, Render, Railway, Timeweb Cloud и т. п.) — GitHub Pages не подойдёт,
потому что нужен сервер для админки и приёма заявок.

```bash
pnpm install
pnpm build
ADMIN_PASSWORD=... AUTH_SECRET=... pnpm start   # порт 3000
```

Чек-лист перед публикацией:

1. `ADMIN_PASSWORD` — сильный пароль; `AUTH_SECRET` — случайная строка (32+ символа).
2. Каталог и фото: `node scripts/seed.mjs` либо заполнить через админку.
3. Заявки: включить Telegram-бота или подключить CRM.
4. Домен: поставить `SITE_URL=https://dvernoitrend.ru` (используется в sitemap и Open Graph).
5. Бэкап: `data/db.json` и папку `public/media` — этого достаточно для полного восстановления.
6. HTTPS обязателен: cookie сессии ставится с флагом `secure` в production.
